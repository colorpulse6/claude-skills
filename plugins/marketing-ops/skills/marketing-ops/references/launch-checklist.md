# Launch Checklist — generic, per product

The reusable skeleton. A product with a dated launch plan overrides this; run the gates in order — a launch that skips Gate 0 manufactures refunds and 1-star reviews.

## Gate 0 — can money and trust actually flow?

- [ ] **Purchase path end-to-end, real card, both directions:** buy succeeds, receipt arrives, access granted; refund works.
- [ ] **Free-tier path:** signup → activation moment reachable in under 5 minutes without docs.
- [ ] **Product-facts file updated** — every claim marketing will make is currently true.
- [ ] Legal pages exist and are linked: privacy, terms, refund policy, imprint/contact.
- [ ] Analytics wired BEFORE traffic: UTM handling, signup source attribution, purchase webhook events. (Unattributed launch traffic is a lesson you only get to not-learn once.)
- [ ] Support surface: an email/inbox someone actually checks, linked from the product.
- [ ] Load sanity: the landing page and signup survive a few hundred concurrent visitors.

## Gate 1 — story assets

- [ ] One-sentence answer to "what is it and who is it for" (everything else derives from this).
- [ ] Landing page passes the 5-second test (a stranger can say what it does and for whom).
- [ ] Demo: a 60–90s video or GIF showing the core loop, no setup shown.
- [ ] Screenshots/gallery in every launch platform's required dimensions.
- [ ] The honest maker story written (why built, what was hard) — it IS the launch post.
- [ ] Store/marketplace listing (if an extension/plugin): title keywords, description, privacy declarations current.

## Gate 2 — audience staging

- [ ] Sandbox channel burn-in done (small account proves format + cadence before the flagship posts).
- [ ] Existing owned audience (list, followers, users) gets the launch note first — they're the warm-start upvotes/comments.
- [ ] Launch platforms sequenced, not simultaneous: e.g. week 1 community-native posts → week 2 Product Hunt → week 3 write-up/SEO. Simultaneous launches split attention you can't reply to.

## Launch day runbook

1. Ship the listing at the platform's optimal time (PH: 00:01 PT Tue–Thu).
2. Post the maker's first-comment immediately.
3. Notify owned audience within the hour.
4. Reply marathon: every comment, all day — questions in answers keep threads alive.
5. Log every feature request/bug publicly ("great catch — on the list").
6. Do NOT ship code on launch day unless it's a fire.

## T+7 review (the part everyone skips)

- Numbers vs baseline: visits, signups, activation rate, purchases, per-channel source split.
- Which channel produced *activated* users (not just visits)? That channel gets next month's effort.
- What did strangers misunderstand? That's landing-page copy debt — fix it now while the confusion is fresh.
- Write the retro note (5 bullets) into the vault; future launches inherit it.
